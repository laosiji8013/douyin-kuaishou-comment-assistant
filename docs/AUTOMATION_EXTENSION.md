# 自动发布扩展指南

本指南说明当前项目已经完成到什么程度，以及维护者如何在授权、可审计的前提下扩展自动发布。它不是绕过平台规则或批量投放无关广告的说明。

## 1. 当前版本不是半成品

浏览器实时模式已经实现完整的单条发布链路：

1. `cli.py` 读取平台、配置、语料、导航方式和运行模式；
2. `SessionRandomizer` 生成观看、浏览动作、点赞候选、取消候选和节奏计划；
3. `run_session()` 执行页面导航与非发布型页面动作；
4. `review_comment()` 抽取、展示和编辑候选评论；
5. 平台适配器定位评论区、输入框和发送按钮；
6. 实时模式将内容填入输入框；
7. 在候选菜单选择发送或完成编辑后，程序按配置停顿并点击发送按钮。

因此，当前缺少的不是“发送按钮代码”，而是无人值守系统必须具备的授权、审核、限速、去重、审计和停止机制。当前默认发布策略是在候选菜单进行一次内容决策，之后自动完成填入和发送。

## 2. 为什么不建议直接删除确认

直接绕过 `review_comment()` 中的启动确认和候选审核，虽然改动很小，却会同时失去：

- 内容与当前视频是否相关的判断；
- 错误文案、过期活动和敏感内容拦截；
- 重复发送保护；
- 账号、活动和时间范围限制；
- 可追踪的审核责任；
- 页面选择器失效时的安全停止。

正确做法是把发布决策抽象成策略，把平台动作抽象成发布器，然后分别测试。

## 3. 推荐模块边界

```text
候选内容 / 活动任务
        ↓
ContentValidator
  - 非空、长度、敏感词、链接、广告标识、相关性
        ↓
PublicationPolicy
  - 账号授权、活动范围、速率、时间窗、人工/自动策略
        ↓
IdempotencyStore
  - 防止同一账号、目标和内容重复发布
        ↓
Publisher
  ├── InteractiveBrowserPublisher（当前候选审核模式）
  └── OfficialApiPublisher（平台官方接口或企业授权能力）
        ↓
AuditLog / StopSwitch
```

推荐接口骨架：

```python
from dataclasses import dataclass
from typing import Protocol


@dataclass(frozen=True)
class PublishRequest:
    account_id: str
    target_id: str
    content: str
    campaign_id: str
    idempotency_key: str


@dataclass(frozen=True)
class PublishResult:
    status: str
    platform_reference: str | None = None
    reason: str | None = None


class PublicationPolicy(Protocol):
    async def approve(self, request: PublishRequest) -> tuple[bool, str]: ...


class Publisher(Protocol):
    async def publish(self, request: PublishRequest) -> PublishResult: ...
```

这段接口不执行任何平台操作。它的作用是让“是否允许发布”与“怎样调用平台”能够独立替换和测试。

## 4. 与现有代码的对应关系

| 当前位置 | 当前职责 | 推荐改造 |
| --- | --- | --- |
| `cli.py` | 读取参数并启动会话 | 增加发布后端选择，但默认仍为交互模式 |
| `randomizer.py` | 生成随机计划 | 保持不变，不负责内容合规 |
| `session.py::review_comment()` | 人工审核、输入和发送 | 拆成内容准备、策略审批和发布器调用 |
| `platforms/base.py` | 浏览器平台能力抽象 | 保留为浏览器发布器依赖 |
| `platforms/douyin.py` / `kuaishou.py` | 网页选择器 | 不与官方 API 凭据混在一起 |
| `config/default.json` | 浏览节奏配置 | 自动发布策略使用单独配置，默认关闭 |

官方 API 发布器应放在独立模块中，例如：

```text
src/comment_assistant/publishers/
├── base.py
├── interactive_browser.py
└── official_api.py
```

凭据只能从环境变量、系统钥匙串或专用密钥管理服务读取，不得写入 JSON、源码、日志或 GitHub Actions 输出。

## 5. 自动发布前必须补齐的能力

### 账号与范围

- 仅允许明确授权的账号；
- 限定允许发布的平台、活动和目标类型；
- 为每个活动设置开始时间、结束时间和停止状态；
- 禁止把测试环境配置直接复制到生产环境。

### 内容审核

- 评论不能为空并符合平台长度限制；
- 检查敏感词、联系方式、外链和广告标识；
- 验证文案与目标内容或用户问题相关；
- 对促销价格、日期和库存等易过期信息设置有效期；
- 高风险内容进入人工审核队列。

### 速率和去重

- 以账号、平台和活动分别限速；
- 使用 `account_id + target_id + normalized_content + campaign_id` 生成幂等键；
- 发布前写入待处理记录，成功后保存平台返回标识；
- 网络失败只重试有限次数，不得无限循环；
- 对重复文案、相似文案和相同目标设置拦截规则。

### 审计与停止

- 记录请求来源、规则版本、审批结果、发布时间和平台返回结果；
- 日志不记录 Cookie、Token 或完整个人信息；
- 提供全局停止、账号停止和活动停止开关；
- 连续失败、投诉、验证页面或账号异常时自动停机并通知人工。

## 6. 测试顺序

### 第 1 层：纯单元测试

- 合法内容通过，空内容和超长内容拒绝；
- 未授权账号拒绝；
- 活动过期或停止时拒绝；
- 速率超限拒绝；
- 相同幂等键只允许成功一次；
- 自动策略关闭时必须进入候选审核。

### 第 2 层：发布器契约测试

对浏览器版和官方 API 版使用同一组契约：

- 成功返回统一 `PublishResult`；
- 平台拒绝、网络错误和超时可区分；
- 重试不会产生重复发布；
- 凭据不会进入异常文本或日志。

### 第 3 层：沙箱或测试账号

- 使用专门测试账号和测试目标；
- 从每次一条开始，不使用真实客户语料；
- 验证停止开关能立即阻止新任务；
- 核对平台后台与本地审计记录一致；
- 页面出现验证码、异常验证或选择器变化时停止，不尝试绕过。

### 第 4 层：小范围上线

- 只开放一个已授权账号和一个活动；
- 设置保守限速和每日总量；
- 由人工抽查发布结果；
- 观察投诉、删除、失败和账号状态；
- 达到预设异常阈值自动回退到候选审核。

## 7. 广告与宣传内容

本项目可以把广告、活动介绍或商品信息作为候选文案交给发布流程，但内容类型不改变平台规则。上线前至少确认：

- 账号具备相应发布或广告资质；
- 素材、品牌、价格和促销信息已获授权；
- 需要标明广告或推广时已经正确标识；
- 文案与目标内容相关，不向无关视频重复投放；
- 不包含虚假承诺、诱导互动或无法验证的效果描述；
- 投诉和撤回有明确负责人。

## 8. 完成标准

只有同时满足以下条件，才应把某个扩展称为“自动发布已实现”：

- 官方或授权发布通道已接通；
- 策略、内容校验、限速、去重、审计、停止开关均有测试；
- 测试账号端到端验证通过；
- 失败和重试不会产生重复内容；
- 凭据扫描为零命中；
- README 写明支持的平台、权限、限制和责任边界；
- GitHub CI 全部通过。

达到这些条件后，维护者可以增加显式的自动发布配置，并继续保持默认关闭。这样交付的是可维护、可审计的系统扩展，而不是删除一行确认代码得到的高风险群发器。
