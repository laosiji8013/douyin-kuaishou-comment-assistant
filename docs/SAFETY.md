# 安全设计与使用边界

## 为什么不是无人值守自动发布

历史原型包含连续自动评论、自动点赞、登录态复用、随机等待和随机页面事件。把这些组合为可直接无人值守运行的公开工具，会显著降低批量垃圾互动的门槛，也可能导致使用者账号受限。

公开版保留了随机配置和平台适配的学习价值，但把发布权交还给用户：

- 默认 `dry-run`；
- 实时模式需显式启动确认；
- 每条评论先选择、可编辑；
- 填入后必须输入 `SEND`；
- 每次点赞单独确认；
- 单次有明确条数上限；
- 没有验证码绕过、代理池、多账号或指纹规避。

## 登录态

Playwright 的持久资料保存在 `browser_data/default/`。该目录可能包含 Cookie、Local Storage 和账号状态，只应留在使用者本机。

仓库已用 `.gitignore` 排除它，但使用者仍应在提交前执行：

```bash
git status --short --ignored
git ls-files
```

## 页面变化

抖音和快手可能随时调整网页结构。找不到按钮时，程序应停止或要求手动导航，不应靠大范围模糊点击继续操作。选择器修复应只针对正常页面适配，不接受验证码绕过或反检测功能。

## 责任

使用者必须查看并遵守平台当前的服务协议、开发者规则和社区规范。开源许可证不等于平台授权，也不承诺账号不会受限。
